- `fhirconnect`: a `manual` entry that writes going into openEHR records a read of each FHIR element its paths name, at the occurrence its mapping binds, so `Outcome::reads` no longer leaves out an element a status table carried. An entry its `fhirCondition` refuses, or one that runs out of openEHR only, records none. `eehrxf` no longer declares such an element lost once a project accounts for it.
