- `ferrobridge-term` 0.1.147 breaks its public API: each FHIR release is a feature, `stu3`, `r4`, `r4b`, `r5` and `r6`, and the default is `stu3`, `r4` and `r4b`. A release whose feature is off has no `WireVersion` variant, so a client in it does not compile. A consumer that speaks R5 or the R6 ballot turns `r5` or `r6` on. `ferrobridge-validator` 0.1.153 enables `stu3` and `r4`, and `ferrobridge-hl7v2` 0.1.204 and `eehrxf` 0.1.186 enable `r4`. The bridge compiles the three releases its `[terminology] wire_version` accepts, so its release build no longer compiles every R5 and R6 resource, which ran the hosted runner out of memory.
