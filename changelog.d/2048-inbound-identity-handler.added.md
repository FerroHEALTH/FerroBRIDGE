- The inbound workers start on every replica that runs both `[inbound]` and the FHIR facade, and apply each stored item through one handler. An upsert reads the source's patient, keeps only its identifiers, names, birth date, gender and deceased status with the tenant's local identifier, feeds it to the identity source as an ITI-104 Add or Revise Patient (`PUT Patient?identifier=<tenant system>|<local id>`), asks ITI-83 for its pseudonym and ensures exactly one EHR for it. A patient the source states merged into another (a `replaced-by` link) is forwarded as an ITI-104 Resolve Duplicate Patient. A remove sends `Patient.active = false` and never deletes an EHR. A refused feed (`400`, `403`, `422`) parks the item; a `5xx`, `429`, `423` or no answer runs it again. A source that declares no resolution parks its items as `resolution-undeclared`. Under `[audit]`, each feed is recorded as the system's PHI import and each EHR the handler creates as a create on the CDR, beside the BALP ITI-104 Source and ITI-83 Consumer records, all in the audit outbox before the step they record.
