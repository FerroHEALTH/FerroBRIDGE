- A template over an ADL 1.4 composition archetype that specialises another, as `openEHR-EHR-COMPOSITION.report-result.v1` specialises `report.v1`, carries one `/context` node, so a mapping that names `$composition/context` resolves against it. Before, the operational template held the composition's `context` twice and every such mapping was refused with `fc-ambiguous-template-node`. The `openehr-*` crates move from 0.0.128 to 0.0.129, which carries the fix, so the next `eehrxf`, `fhirconnect`, `openehr-mapping-core` and `ferrobridge-hl7v2` publish requires `openehr-* ^0.0.129`.
