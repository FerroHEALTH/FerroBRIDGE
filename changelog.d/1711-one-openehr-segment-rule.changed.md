- FHIRconnect and OMOCL now match a written openEHR path against a template by one segment rule, `openehr_mapping_core::index::matching::segment_matches`, which the Web Template index already used. A segment that writes no node id names every node of its attribute. A name or a position is compared only when both the mapping and the template carry one. A descendant step names no template segment. Before this change, FHIRconnect matched a segment without a node id only to a template segment without one, and OMOCL compared no names. The ITS-REST client of the server answers a found template as the foundation's `TemplateSource`, so the workspace has one template source type.
