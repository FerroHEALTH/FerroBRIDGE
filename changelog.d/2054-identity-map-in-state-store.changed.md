- The FHIR facade keeps its identity map in the PostgreSQL state store, which every replica shares, in place of a `redb` file. Each binding is recorded once, so two replicas recording one binding agree on the one that stands. No identifier value is stored in clear: a subject identifier and every `Resource.identifier` value are stored as an HMAC-SHA-256 under the new `[state.seal] lookup_key` (or `lookup_key_file`), and the subject an EHR was recorded for is sealed with AES-256-GCM under a `[state.seal]` key. The store pins the identity derivation and the lookup key's fingerprint, and refuses to start under another. Upgrade note: `[facade] identity_store` is removed; an enabled facade needs `[state]` and `[state.seal]` with a `lookup_key`, the map starts empty, and the old `redb` file is no longer read.
