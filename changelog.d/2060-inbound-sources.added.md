- Inbound sources are versioned rows of the state store, so an operator adds, changes, disables or deletes the source of patient events (a `webhook`, a `fhir-subscription` or an `mllp` sender) without a restart and without a new port. The operator API serves `GET` and `POST /operator/sources`, `GET`, `PUT` and `DELETE /operator/sources/{id}` with the version as the `ETag` (a stale `If-Match` answers `412`, a missing one `428`) and `GET /operator/sources/{id}/versions`, every version kept with its committer, deletions included. One write validates the kind's document, derives the source's tenants and MLLP routes, and notifies every replica, whose `LISTEN` session reloads the source into its snapshot; a replica whose session is down reads the row on every lookup. A document names its secrets (`{"secret": "<name>"}`), which resolve through the new `[secrets]` directory (`dir`, `poll_seconds`, read again without a restart); a write naming a missing secret answers `422` and a secret missing at runtime fails the source closed with `503`. The operator console gains the Sources pages: the list, one source with its versions, and the edit form. New problem types: `invalid-source`, `source-conflict` and `sources-unavailable`.
