- Breaking: the bridge moves to `ferrohealth-smart` 0.32.0 and `ferrohealth-session` 0.27.0, and `[auth]` takes their simpler issuer configuration. Each trusted issuer is a named table, `[auth.issuer.<name>]`, in place of the `[[auth.issuer]]` array, and `described_issuer` names a table by its name. An issuer that sets no `audience` takes `[facade] base_url`, and `kind` defaults to the preset's (`persons` under `ferrosmart`, `keycloak`, `entra` and `okta`). The preset is `preset = "…"` in place of `profile = "…"`, every profile key (`first_party_clients`, `delegates`, `app_only`, `token_types` and the rest) moves into the issuer's `[auth.issuer.<name>.profile]` table, and `profile_file` reads a profile file you supply. `scopeless_subjects` moves onto its issuer table as a list of `sub` values. The onward tables follow: `[cdr.endpoint.credentials.onward]` and `[[cdr.onward]]` take `preset` and a `profile` table in place of `profile` and `keys`. Upgrade: give each `[[auth.issuer]]` table a name, rename `profile` to `preset`, move its profile keys under `.profile`, drop an `audience` equal to the facade's base, and set `described_issuer` to the name.
- Breaking: the facade reads a token's `patient` claim as the launch context only from an issuer whose profile sets `patient_context`, the per-issuer rule FerroEHR reads too. The `ferrosmart` preset sets it; under any other preset a `patient` claim is ignored, so a `patient/` scope reaches no patient, until the issuer's profile table sets `patient_context = true`. Behind FerroSMART no self-delegate is needed for its patient picker (`issuer_client_is_person`), and `audience_delegates = true` admits every app registered at FerroSMART for the facade without a `delegates` entry.
- Breaking: every `401` and `403` `Bearer` challenge with an error code carries the stable reason code of the check that refused the token as its `error_description` (RFC 6750 §3), such as `expired`, `audience-mismatch` or `scope-not-granted`. The `OperationOutcome` and the problem body are unchanged and still name no claim and no scope.
- `ferrobridge-term` carries smart types in its public API, so it moves to 0.16.0, and the crates that require it follow: `ferrobridge-validator` 0.16.0, `ferrobridge-hl7v2` 0.24.0 and `eehrxf` 0.22.0. A dependant moves `ferrohealth-smart` to 0.32 with them.
