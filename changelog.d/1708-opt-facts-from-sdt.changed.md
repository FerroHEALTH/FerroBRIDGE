- `openehr-mapping-core`, `fhirconnect` and `eehrxf` read the operational-template facts of a node (the embedded template id, the archetype's term definitions, the ordinal options), the FLAT key of an RM attribute and the relative path between two nodes from `openehr-sdt` instead of walking the OPT 1.4 themselves. An archetype root below an OPT 1.4 `T_COMPLEX_OBJECT` now answers its embedded template and terms in the index, as it already did in `eehrxf`. Breaking for a crate consumer: `eehrxf::terminology::local::TermDefinitions::from_template` returns a `Result` (a template that builds no Web Template is `TermDefinitionsError::Build`); `fhirconnect::engine::rm::ENTRY_TIMES` loses its key column and `family_of` takes the owning class and answers an `Option`; `openehr_mapping_core::index::paths::relative` no longer returns `MalformedAqlPath`.
