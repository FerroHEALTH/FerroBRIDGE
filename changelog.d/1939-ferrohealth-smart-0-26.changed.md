- Breaking: the server keeps an overload bound always: `[server] max_concurrent_requests` is 256 by default, where unset left the server unbounded, so past 256 requests in flight a request is answered `503` with `Retry-After` and the health routes are never refused. A deployment that relied on no bound sets the ceiling it wants (FerroHEALTH/FerroEHR#5743).
- The crates move to `ferrohealth-smart` 0.26 and `ferrohealth-server` 0.10. `ferrobridge-term` 0.11.0 takes smart's `EndpointSection` and `OutboundClient` from the 0.26 line in `Client::from_endpoint`, so a dependant on smart 0.26 passes its own types. `ferrobridge-validator` 0.11.0, `ferrobridge-hl7v2` 0.16.0 and `eehrxf` 0.14.0 follow `ferrobridge-term` 0.11. The server takes `ihe-atna` and `ehds-logging` 0.21.0, and the operator console takes `ferrohealth-session` 0.21.0, the releases on the same smart line, so one smart, one server and one telemetry link.
