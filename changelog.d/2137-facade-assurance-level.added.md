- The facade checks the eIDAS level of assurance of every access token. Each `[auth.issuer.<name>.assurance]` table maps the issuer's `acr` values to `low`, `substantial` or `high`, and the new `[assurance]` section names the level the FHIR routes (`fhir`) and the SMART Health Link routes (`shl`) require. A token below the level, a token with no mapped `acr` and a Basic credential answer `401` with an `OperationOutcome` and the RFC 9470 §3 challenge `Bearer error="insufficient_user_authentication"`, naming the accepted values in `acr_values`. An issuer's own `minimum` now holds on every guarded route. The facade's access record carries the level of each admitted caller. A minimum no issuer reaches, or one set while `[auth]` is off, refuses the start.
