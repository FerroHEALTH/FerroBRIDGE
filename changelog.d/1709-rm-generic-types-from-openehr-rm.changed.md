- `fhirconnect` and `openehr-mapping-core` read a generic RM type name (`DV_INTERVAL<DV_QUANTITY>`) and the class an attribute holds below it through `openehr_rm::v1_2::typing` (`RmType`, `base_name`, `attribute_type`) instead of splitting the name by hand. Breaking for a crate consumer: `fhirconnect::resolve::derive::base_class` is gone (use `openehr_rm::v1_2::typing::base_name`), and `derive::type_argument` answers an `RmType`.
