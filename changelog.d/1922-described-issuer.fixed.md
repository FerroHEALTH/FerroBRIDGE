- The SMART discovery document and the facade's `CapabilityStatement` name the issuer `ferrohealth-smart`'s shared rule describes, never the first `[[auth.issuer]]` table. `[auth] described_issuer` names it; without the key the bridge describes the one issuer of kind `persons`, `patients` or `federation` whose metadata it holds, and a bridge that trusts only `machines` issuers describes its one `machines` issuer for SMART Backend Services alone: the token endpoint, the client credentials grant and `private_key_jwt`, with no authorization endpoint. Breaking: a bridge that trusts several such issuers and sets no `described_issuer` refuses the start, naming them and the key, and so does a `described_issuer` that names an unknown issuer, an issuer without metadata, or a `machines` issuer beside one that serves a user launch.
