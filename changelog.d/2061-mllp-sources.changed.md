- HL7 v2 senders are `mllp` inbound sources of the state store, routed by MSH-3 and MSH-4, so adding a device is one `POST /operator/sources` call that every replica takes up without a restart. A route holds the certificate subject the TLS listener checks against the client certificate's SAN, or the CIDR networks the plain listener checks against the peer address per message, and carries the sender's settings (`origin`, `device_identifier_issuer`, `profiles`, `unmapped_entries`, `ehr_policy`, `default_charset`, `facility_identifier_issuer`, `log_outcomes`). A message whose route the connection does not match is answered `AR` and its plain connection closes; a message the store cannot route is answered `AE`. The TLS listener reads its client CA file again when it changes. `[hl7v2]` now needs `[state]`, and its `senders`, `profiles`, `default_charset`, `unmapped_entries`, `facility_identifier_issuer`, `ehr_policy` and `log_outcomes` keys are removed: to upgrade, write each former sender as an `mllp` source through the operator API. The health document's HL7 v2 lane no longer lists senders.
