# ferrobridge-term

The hand-written FHIR terminology client. The oracle is the HL7 FHIR
specification for the release in play: the `OperationDefinition` of each
operation under `tools/fhir-codegen/vendor/hl7.fhir.r3.core`,
`hl7.fhir.r4.core` and `hl7.fhir.r4b.core` for every parameter, and the
operations framework (<https://hl7.org/fhir/R4/operations.html>) for the
invocation and the failure shape.

- **The contracts come from `fhir-types`, never from hand-written JSON.**
  `fhir_types::stu3::operations`, `fhir_types::r4::operations` and
  `fhir_types::r4b::operations` carry the request and response types with
  `from_parameters` and `into_parameters`. A shape that is wrong or missing is
  a generator fix, never a local type (`.claude/rules/codegen.md`).
- **One module per release, generated by the `per_release` macro in
  `wire/release.rs`.** The decoders are written once. The request writers are the
  release's contracts macro (`wire/contracts.rs`): R4 and R4B declare identical parameter sets and
  share `r4_contracts`; STU3 has `stu3_contracts`. Verify any claimed
  per-release difference against the vendored `OperationDefinition` files
  before encoding it.
- **A parameter a release does not declare is refused, never dropped.** STU3
  has no `$translate` `url` and no `$validate-code` or `$expand`
  `valueSetVersion`, so a
  request naming one is `Error::UnsupportedParameter` before anything is sent,
  and `Client::check` answers the same question without sending, so a
  caller can set such a request aside before a batch.
  A parameter STU3 declares under another name (`version` for R4's
  `systemVersion`) is mapped, with the citation beside the mapping.
- **A negative answer stated in `out` parameters is an outcome; a refusal is an
  error.** `LookupOutcome::NotFound`, `TranslateOutcome::NoMatch`,
  `ValidateOutcome::Invalid` and `ExpandOutcome::NotFound` are outcomes.
  Everything else keeps the upstream status and body in a typed error, a
  `$subsumes` that cannot decide included. Nothing is ever flattened into
  `None`, a default, an empty expansion, or an empty display.
- **Which refusal means "not known" is our own decision**, flagged in
  `decode.rs`: no FHIR clause fixes the status or the issue code, so the client
  reads the `tx-issue-type` classification and falls back to a bare `404`.
  `$expand` reads only `not-found` that way, since `invalid-code` names a code.
  Change it only with a citation.
- **`$expand` answers the `ValueSet` itself**, the operations framework's
  rule for a single resource `out` parameter named `return`; a `Parameters`
  wrapper is a decode error.
- **`translate` never decides for the caller.** Every match is returned with
  its equivalence; `accepted()` yields `equivalent` and `equal` alone. A
  refusal fails closed and is never a missing translation.
- **Retry covers connect failures, timeouts and `5xx` only**, and the `POST`
  form is retried because the five operations declare `affectsState: false`;
  the `CodeSystem` count search is a `GET`.
  The predicate is `Error::is_retryable` and it is tested.
- **The log carries the operation, the URL path and the status.** A code is a
  clinical fact: never log a body, a code, or a query.
- **Tests are `wiremock` contract tests through the testkit stubs**, one case
  per outcome and per error family, every release per operation, plus the
  container run behind `FERROBRIDGE_E2E=1`. Every fixture is synthetic.
